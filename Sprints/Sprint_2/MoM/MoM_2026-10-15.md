## Agenda and purpose

Dr. Schlosser shared updates from his work and his meeting with Dr. Nick Crookston. We discussed the data FVS needs, how it may reach FRASS, and what to run next.

## Key discussion points

### Recent updates

- Dr. Schlosser attended a forestry conference in Tacoma, where FRASS was presented.
- He met with Dr. Crookston and asked us to follow the FVS documents Dr. Crookston shared.
- We will meet with the other capstone teams to work out how data will move between their apps, FRASS, and FVS.
- Our local R-driven FVS run is a starting point. The goal for next week is to run FVS on Serviak.

### Input data

- Flex Cruiser is the other team's mobile app for recording tree measurements such as species, diameter, height, and crown. We need to learn exactly what it sends back and how it will combine with GIS data.
- Location helps determine habitat type, site index, and the FVS variant. We need to map where each value comes from.
- Dr. Schlosser asked Jake to work on the Cruiser user type.
- We need the client's tree and stand data from OneDrive. Data such as site indexes should be available to FRASS when it prepares a run.
- Cruiser may record fields FVS does not need, such as stump height. Dr. Crookston advised us to keep the full record; FVS can use the fields it needs. We still need to test the actual import format.
- Keep site indexes for each species when they are available. Do not reduce them to one value before we know what the FVS variant needs.
- The teams discussed SQLite as the data handoff format. We still need to agree on the tables, fields, and conversion steps.

### Runs and results

- Start with one stand, possibly using a Douglas-fir site index.
- For the next sprint, the goal is a Serviak run that takes tree input and produces SQLite results. Reid's demo SQL files are examples to examine.
- One example would take inventory data from the 2010s and grow it to 2026. The results could feed Flex Taper.
- A later Year Zero run would use current Cruiser and GIS measurements without growing the stand. It should provide starting data for cubic-foot volume and Flex Taper. Dr. Schlosser wants this before January 1.
- FRASS needs the FVS results back after a run.

### Tracking the data

- Each Cruiser measurement should be traceable to the person who recorded it and to anyone who checked it.
- Dr. Schlosser said to use Cruiser elevation when both Cruiser and GIS have a value. Acreage should come from GIS.

## Decisions and clarifications

- Keep the original Cruiser data, including fields FVS does not use, and keep species-specific site indexes when available.
- Use Cruiser elevation over GIS elevation and use GIS acreage. We still need rules for missing values.
- Work toward a Serviak run, SQLite output, and a return path into FRASS in Sprint 2.
