## Agenda and purpose

## Key discussion points

### Existing system and input data

- FVS was described as a simulation model that takes field samples and projects tree and stand growth. It can be controlled through text, including a required keyword file, while other input and manipulation can use SQLite databases.
- FRASS uses a SQL Server database and mostly C# application code. FVS input would need stand/site and tree-level data in an FVS-compatible SQLite database. Stand IDs connect stand and tree records.
- Some field inventory input is already in SQLite and refer to a C# conversion tool. The team should verify which sources and conversion steps actually exist in the inherited system.
- Required and missing fields need careful treatment: distinguish missing (`NULL`) values from estimated values. Specific FVS field requirements still need to be documented.
- A FRASS user may have data already in FRASS or may bring an external FVS-ready source. The input flow should be explored for both cases.

### Proposed FVS execution path

- Obtaining the official Forest Service FVS distribution and keeping the library updated through FRASS maintenance. FVS DLLs were already installed on Serviak at the time of the meeting; this has not been independently verified in this MoM.
- FVS Online was described as an R-based way to build a run from stands in an input database, using `fvsOL` and `rFVS` functions instead of hand-writing every keyword command. The team discussed calling functions without starting the graphical interface.
- The run configuration can be represented as an R object. We want to preserving that object and make it available for users who want to create or inspect runs locally.
- The intended pipeline discussed was: obtain FRASS or user data; translate it into FVS-compatible SQLite tree/site inputs; construct a run through R/FVS Online; execute FVS using the appropriate regional DLL; and bring the output database back into FRASS for later analysis, including flex taper.
- Run options discussed included user-selected site, years, and other factors. Default of ten ten-year increments and a baseline with one-year increments.
- When FVS Online runs locally, R as the server and a browser as the client. The intended FRASS user interface and deployment boundary remain open design questions.
